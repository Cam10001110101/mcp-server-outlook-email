# MCP 2026-07-28 implementation and verification

The target is the [2026-07-28 specification](https://modelcontextprotocol.io/specification/2026-07-28),
including its schema, rather than the older 2025-11-25 schema page. Python 3.11+
and the official `mcp`/`mcp-types` 2.3.0 SDK implement the protocol. `uv.lock`
records the tested dependencies for all supported platforms and extras.

## Supported protocol surface

| Requirement | Implementation and regression coverage |
| --- | --- |
| Discovery and per-request negotiation | `server/discover`; native requests work before discovery or initialization; unsupported revisions return `-32022` and supported versions; a later valid request still works. |
| Results and identity | `resultType: complete` and server identity metadata on results; no server-initiated requests. |
| Capabilities and catalogs | Eleven tools, one static resource, three templates, five prompts; deterministic listings independent of connection history. Subscriptions and list-change notifications are not advertised. |
| Cache metadata | All cacheable methods explicitly use `ttlMs: 0`, `cacheScope: private`; mailbox content must not be shared across authorization contexts. |
| Tool schemas and errors | JSON Schema 2020-12 input/output schemas, typed structured content with matching text content, invalid arguments rejected, application `success: false` reflected as MCP `isError: true`. |
| Resource and prompt operations | Resource reads and prompt retrieval; missing resources and invalid URI arguments produce `-32602`, backend resource failures produce `-32603`. |
| Progress | Numeric, strictly increasing progress with numeric total and textual message; emitted only when the originating request includes a progress token. |
| Stdio | Real subprocess JSON-RPC framing, stdout contains protocol messages only, EOF shutdown, native July requests and legacy SDK initialization. |
| Streamable HTTP | Stateless requests with matching version/method/name headers, JSON or request-scoped SSE replies, no session IDs or resumable SSE event IDs, modern GET rejected. |
| HTTP security | Loopback binding, Host/Origin validation, rejected batch requests and duplicated/mismatched routing headers, bounded bodies before parsing. |

SDK 2.3 routes HTTP by the version header before examining the body. A small
application middleware closes the resulting legacy-routing gap: a request with
per-request version metadata must have exactly one matching version header,
otherwise it receives HTTP 400 and `HeaderMismatch` (`-32020`). An outer SDK
body limit runs before that middleware reads any bytes. The normal SDK dispatch,
schema validation, cancellation and transport machinery remain in use.

Mailbox services initialize on the first data operation, so discovery and schema
inspection do not contact MongoDB, Ollama, Graph or Outlook. Protocol tests use
synthetic data and temporary files. They include export traversal rejection for
CSV, HTML, JSON and Excel's JSON fallback, preserving the issue #7 mitigation.

## Reproduce verification

```sh
uv sync --locked --extra dev --extra all
uv run --locked pytest -q
uv run --locked ruff check src/security_utils.py src/exporters.py src/protocol_support.py tests .github/scripts
uv run --locked bandit -r src -ll
mkdir -p /tmp/outlook-dependency-audit
uv export --locked --all-extras --no-emit-project --format pylock.toml --output-file /tmp/outlook-dependency-audit/pylock.toml
uv run --locked pip-audit --locked /tmp/outlook-dependency-audit --strict
```

The dependency audit on 2026-11-12 found no known vulnerabilities in 94 locked
runtime, development, build and optional packages, including the Windows extra.
CI runs regression tests on Linux, macOS and Windows with Python 3.11–3.14.
Native Outlook/Graph access and real mailbox processing require separate
integration testing with an explicitly configured test account.

## Scope and deployment

Conformance applies to the features this server implements. Optional tasks,
sampling, elicitation, roots, completions, extensions and subscriptions are not
application features and are not advertised. Implementing every optional
feature is not required by MCP. The SDK retains compatibility for legacy clients.
The finite regression suite is evidence of behavior, not an independent claim
of universal or certified “100% compliance.”

The HTTP endpoint remains local and unauthenticated; it is unsuitable for
multi-user or public deployment without authentication and isolation. MCP host
consent, review of sensitive operations and treatment of mail as untrusted
content remain part of deployment. Stdio is the default desktop transport.
